## 5. Known errors / issues

### A. `npm test` — 13 platform failures (not GST app tests)

Template tests assume shipped `VITE_AUTH_ENABLED=false` in `.grok/app-env.json`. This app correctly leaves auth ON (per-user GST data), so:

- `with-app-env.test.mjs`: “the template ships auth off”; wrapped command expects `'false'`, gets `undefined`; symlink CLI same.
- Several grok-pwa / og injector tests (`not ok` 89, 101, 105–107, 109, 110, 113) and “auth schema ships outside the globbed directory” (132); “build side resolves the template's shipped app-env” (79).

These are **workspace-template invariants vs product auth-on**, not runtime crashes of Pramaan.

### B. Local preview without Grok gate session

Unsigned local browsers see login, not the seeded ledger. Expected with auth ON. Grok live preview is supposed to gate-sign-in.

### C. Production build vs current source

After the last successful production build, `_app.tsx` gained `throw redirect({ to: "/login" })` and AppShell loading copy changed. Rebuild before claiming production-preview parity.

### D. `generateEinvoice` 30-day reject path

Odd indentation in `server.ts` around the IRP window failure update; logic present, not typecheck-broken.

### E. HSN table in GSTR-1

HSN map accumulates taxable + qty only; CGST/SGST/IGST columns stay 0.

### F. No GST-specific automated tests

Tax engine / invoice save / IRN window untested by `npm test`.
